# Which CouchCHD setup fits my device?

Read the **full model suffix** on the case and the **running firmware** in Settings → About. An RG Cube and an RG CubeXX take different routes. On a dual-boot handheld, the answer can change after a reboot.

| What you want | What runs where |
| --- | --- |
| **Compress games** on a Steam Deck, Bazzite PC or Pi 4 | [Install the Linux app](../README.md#install-from-github). The release needs **x86-64 or AArch64, 64-bit Linux userspace and glibc 2.36+**. The UI also needs graphics and input drivers; on ARM without a desktop session this means compatible EGL/KMS. A 64-bit CPU with a 32-bit OS is not enough. No release converter for Android, Windows, macOS, MIPS or musl-only Linux. |
| **Leave the card in an Android handheld** | Install [CouchCHD Receive](https://vip3rousmango.github.io/couchCHD/receive/) on **Android 8.0+ (API 26)**. On the same home LAN, connect and confirm matching codes on both devices **before** choosing games. Grant Receive the existing folder for one platform, then rescan in the frontend. The APK receives games; it doesn't convert them or sync saves. [RG405M / Daijishō walkthrough](../README.md#anbernic-rg405m--android--daijishō) |
| **Copy to an existing games card** (Linux or Android) | On the host, choose [Prepare a game pack](../README.md#choose-a-handheld-by-firmware-and-player). A profile filters ready files for a firmware/player; it doesn't detect hardware or install software. Use the mounted **games** volume, not a boot card. Identical files are skipped; different files at the same path aren't overwritten. For MTP, stage first; CouchCHD cannot verify the final manual copy. |

**Where the Linux app appears:** Steam Deck → **Non-Steam**; Bazzite/KDE → **Utilities**; Recalbox, Batocera and supported ROCKNIX images → **Ports**; RetroPie → **RetroPie configuration**. These are [launcher integrations](../README.md#launchers-and-updates), not proof that the binary or display works on every board using that frontend. RetroDECK users launch from the host desktop or Steam, not inside the Flatpak.

## Find your ANBERNIC model and firmware

These are **export choices**, not native installs or playback certifications. Match the firmware *and* the installed player. The [shipping profile list](../src/couchchd/handheld_profiles.py) includes every model, accepted extension and folder; `couchchd --handheld-profiles` lists the choices in your installed build.

| Model / running firmware | What to choose and where to copy |
| --- | --- |
| **RG405M** on Android | **RG405M · original pack** for the original PS1, Dreamcast and PSP layout. PS1/Dreamcast accept single CHDs or complete relative M3U playlists of CHDs. For an older or unknown PPSSPP, choose **CSO only**; the DVD CHD player preset is **1.17.1+**. For custom platform folders use **Android · T618**, also listed for RG405V and RG505. |
| **RG Cube, RG556, RG406H/V** on Android | **Android · T820**. RG557 and RG477M/V use **Android · other current families**. Choose the installed player and its actual platform folder; Daijishō isn't required. **RG CubeXX** is stock Linux, not a smaller Android Cube. |
| **RG353M/P/V, ARC-D, RG552** | On Android choose **Android · RK3566 / RK3399**; check the installed Android version before trying Receive on RG552. On Linux use the matching firmware row below or a manual folder. **RG353VS/PS, ARC-S and RG503** ship with Linux; use **GammaOS Core · RK3566** only if already running that alternative Android 13 TV firmware. No flashing is needed for card export. |
| **RG280V/M, RG300X, RG350/P/M** on Adam image 2.1 | Choose **Adam image**, not stock OpenDingux. Use the external `roms` directory: `PS` for a single PlayStation CHD with CHD-capable PCSX4All; no playlists. Optional cartridge `.7z` means one ROM, not an arcade set. |
| **Original RG35XX** vs **RG35XX H/Plus/SP, RG40XX H/V, RG CubeXX** | **MinUI:** use the existing `Roms/… (PS)` folder; the preset exports single PS1 CHDs only. **KNULLI** on the listed H700 models: use active `SHARE/roms`. **muOS:** choose an existing platform folder under `ROMS` and confirm its assigned core. Original RG35XX is not a KNULLI target. Stock/Garlic is not MinUI. |
| **RG351 / RG353 / RG503 / ARC** on custom Linux | **ArkOS:** use the active EASYROMS partition. **dArkOS:** among RG351 models the preset lists **MP only**, not P/M/V. Both presets exclude Sega CD and PC Engine CD playlists. **ROCKNIX:** use the active `roms` directory; its RG351 preset lists **P/M/V**, not MP. An upstream firmware build isn't necessarily a shipping CouchCHD preset. |
| **RG VITA Pro, RG DS** or a model/firmware not listed | VITA Pro and DS on Android use **Android · other current families**; VITA Pro on muOS uses **muOS**. DS **Plus** is stock Linux. For stock Linux, AmberELEC, GarlicOS or another unlisted combination, use **Other handheld · confirmed player** only if its menu lists the extension and you know the reader and platform folder. Otherwise keep the known-working format. |

**What is verified?** The [release gate](../.github/workflows/release.yml) uses a signed APK on an Android 12 emulator. It [checks both peers’ confirmation and hashes the received disc fixture and playlist](../scripts/smoke_android_receive.py); it doesn't test physical LAN broadcast or play a game. The [original RG405M pack has host-side export tests](../tests/test_handheld.py); the other named presets describe documented destinations. Before copying a batch, try one title: confirm the frontend lists it, start gameplay, reload an in-game save and, for a playlist, change discs. Keep your originals.

For model specifications, alternate firmware and player-specific limitations, see the [Android device research](anbernic-android.md) and [Linux firmware research](anbernic-linux.md). Package requirements come from the [Linux installer](../scripts/install-device.sh), [release workflow](../.github/workflows/release.yml) and [Android manifest](../android/AndroidManifest.xml).
